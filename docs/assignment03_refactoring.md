# Задание 3. Рефакторинг «плохого» кода

## Исходная функция

Файл: `backend/app/legacy_bad.py` — функция `calc(...)` с 23 позиционными параметрами-флагами.

### Проблемы

| Проблема | Пример в коде |
|----------|----------------|
| Длина > 30 строк | ~45 строк с повторяющимися `if k == 1: t1 += ...` |
| Магические числа | `0.9`, `0.95`, `500`, `0.15` без имени |
| Нет обработки ошибок | Не проверяется `nights <= 0`, отрицательная цена |
| Неинформативные имена | `x`, `y`, `z`, `a`…`w` |
| Дублирование | Повторяющиеся блоки скидок и надбавок |

## Исправленная версия

Файлы: `backend/app/services/pricing.py`, `backend/app/services/stay_charges.py`

### Изменения

1. **Именованные параметры** — `price_per_night`, `check_in`, `check_out`, флаги `is_loyalty_guest`, `is_peak_season`.
2. **Константы вынесены в логику с комментариями** — 10% за ≥7 ночей, 15% пик, 500 ₽/час штраф.
3. **`ValueError`** при некорректных датах.
4. **Dataclass `PricingResult`** — прозрачная структура ответа и `breakdown` для отладки.
5. **Удалено дублирование** — одна функция `calculate_stay_price` вместо 20 веток `if *_ == 1`.
6. **Тесты** — `backend/tests/test_pricing.py`.

## Сравнение вызова

calc(8, 3, 10000, 1, 0, 1, 0, ...)
